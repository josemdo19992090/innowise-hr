# HR Scout — оценка кандидатов с ИИ

MVP для HR небольших компаний: загрузка резюме (PDF) → оценка ИИ относительно вакансии → рейтинг → чек-лист собеседования → статистика.

Stack: Next.js (App Router, JS), Tailwind CSS, Gemini API (REST), `unpdf` для извлечения текста. Хранилище и логин (опционально) — Supabase: одна jsonb-строка на пользователя/гостя в таблице `kv_store`, аутентификация — Supabase Auth (email+пароль). Без Supabase переменных приложение работает как раньше: один локальный пользователь, без логина, данные в `data/*.json` (см. `lib/db.js`).

## Запуск локально

```bash
npm install
cp .env.local.example .env.local   # добавить GEMINI_API_KEY
npm run dev
```

Открыть http://localhost:3000.

`.env.local`:

```
GEMINI_API_KEY=...
GEMINI_MODEL=gemini-3.8-flash   # можно сменить без правок кода; см. доступные модели на aistudio.google.com/apikey

# опционально — включает логин и постоянное хранилище через Supabase
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
```

Бесплатный тариф Gemini ограничен ~5 запросами в минуту — загружать резюме партиями по 4–5.

## Логин и хранилище (Supabase)

1. Создать проект на [supabase.com](https://supabase.com) (бесплатно).
2. **SQL Editor** → выполнить:
   ```sql
   create table kv_store (
     key text primary key,
     value jsonb not null
   );
   ```
3. **Authentication → Sign In / Providers → Email** → выключить **Confirm email** (иначе после регистрации нужно подтверждать почту, прежде чем можно будет войти).
4. **Settings → API** → скопировать Project URL, `anon public` и `service_role` ключи в `.env.local` (или в Vercel, см. ниже).

Без входа в аккаунт приложение работает в гостевом режиме: всё функционирует как обычно, но ничего не сохраняется — при перезагрузке страницы данные исчезают.

## Деплой на Vercel (публичная ссылка)

1. Запушить репозиторий на GitHub, импортировать в [vercel.com](https://vercel.com) → New Project.
2. Через интеграцию **Supabase** (маркетплейс Vercel) подключить тот же проект Supabase — она сама создаст нужные переменные окружения.
3. **Settings → Environment Variables** — добавить `GEMINI_API_KEY` и `GEMINI_MODEL`.
4. Deploy.

## Демо-сценарий

0. `/` — главная: что это за инструмент, шаги и что делает каждый раздел.
1. `/vacancy` — вставить текст из `samples/vacancy.txt`, сохранить.
2. `/candidates` — загрузить все PDF из `samples/` (или реальные резюме). Файлы обрабатываются параллельно (по 2), рейтинг обновляется по мере готовности.
3. Открыть кандидата → отредактировать чек-лист, выставить оценки 1–10, сохранить собеседование.
4. `/stats` — средние баллы и самые слабые компетенции по всем собеседованиям.

Демо-резюме можно пересоздать: `node scripts/make-samples.mjs` (использует Arial из Windows; путь меняется через `CV_FONT`).

## Решения

- **Один вызов Gemini на кандидата**: оценка + чек-лист в одном JSON (экономия квоты free tier). `responseMimeType: application/json` + очистка ``` и try/catch; ошибки показываются по каждому файлу, страница не падает.
- **Поддержка, а не отказ**: промпт запрещает вердикт «подходит/не подходит» и учёт защищённых характеристик — только балл и доказательства.
- **JSON-файл вместо БД**: записи сериализуются через promise-очередь, чтобы параллельные загрузки не перезаписывали друг друга.
- **Ограничения MVP**: только PDF с текстовым слоем (сканы без OCR дают понятную ошибку), одна активная вакансия на аккаунт, сохранённые собеседования не редактируются.
- **Гостевой id живёт только в памяти вкладки**: генерируется заново при каждой полной перезагрузке страницы и нигде не сохраняется — старые гостевые данные становятся недостижимы (по сути удалены), а не переживают перезагрузку.
- **Добавить кандидата вручную**: тот же формат записи, что и у оценки ИИ, только поля заполняет рекрутер сам — на случай, если кончилась квота Gemini или просто не нужен ИИ для этого кандидата. Кнопка есть всегда рядом с загрузкой, и появляется прямо у каждой неудачной попытки оценки — файл резюме при этом остаётся прикреплён к записи.
